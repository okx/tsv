## 未覆盖位置的分类

以下位置保留事实记录，避免把所有零计数都算成可正常触发的业务缺口。需要依赖故障或未来实现才能出现的状态，可额外建立防御测试，不能声称它们已经测试。

| 分类 | 位置与判断 |
| --- | --- |
| 当前公开写入约束下不可达；可选故障注入 | Hook `_requireExactKey` 的 Registry key 与其 poolId 不一致；Hook/Ledger 股票 securityId、Adapter 或版本异常。当前登记/更换入口维持这些关系；需要异常 Registry 返回或升级破坏约束才能触发。 |
| 被前置检查或固定入口挡住；可选内部 harness | LP `collectFees` 中 liquidity=0 的检查已被 `_requireOwner` 拒绝；Receipt 对非零 owner 的内部 `_update` 转移已由公开 transfer/approval 入口拒绝；unlock 回调的过期条件已在同一交易前检查，正常 EVM 中时间不会在一笔交易内变化。 |
| 正常生命周期不产生；可选异常依赖测试 | LP 强退时“活跃仓位所属池不再 known”。当前 Registry 没有删除已登记 Pool 的入口，停用仍然 known。 |
| ABI/日期范围限制 | MarketAction 越界在解码处拒绝，函数体最后 invalid action 分支不可触达；有效 1970–9999 日期不会使 TradeDayLib 的 uint64 timestamp 溢出。参数非法拒绝已有测试。 |
| 已执行但 IR 映射未计入 | Registry SBT 配置校验、配置事件及门禁成功返回；Router/LP 正负结算判断；Hook 普通移除/强退分支。对应行为有通过断言，不能仅依据 LCOV 的某一行/分支零计数再记一项缺失。 |
| 历史代码范围 | `src/v1/legacy/` 的旧包装结算 Adapter 不属于当前 V1 路径。其未覆盖分支影响源码总体百分比；当前部署不使用它时，不纳入 V1 补测任务。若重新接入，单独验收。 |

LCOV 对主路径仍有部分未计入位置；TG-01 至 TG-04 由源码与现有用例共同确认，未统一归因于映射。治理 Anchor 100% 覆盖不能替代 TG-08/TG-09。

## 已实现的拆并股规则与保留边界

2026-10-04 用户确认保留当前日均 ADTV 上报和 Tier rate，新增独立拆并股系数，并将生效时间限制为**未来计量日开始**。公式为 `floor(adtvWad × tierBps × numerator / (10000 × denominator))`，不支持日内切换，所以不用换算同日已用量；旧日用量原样保留，新日独立累计。

系数按 `(securityId,sourceMonth)` 保存相对该来源月单位的绝对累计值；连续事件报告累计比例。来源月 ADTV 使用月末单位，同月数据更正维持该基准；新月 ADTV 已含的事件不再次排期。quota 仍为目标日单位的绝对覆盖值，按需 SET/CLEAR，不能假定它也自动乘系数。

排期由 VOLUME_ORACLE_ROLE 直接提交，版本、kind=3 序号、全局唯一 ID、deadline 和 freshness 均校验；只有最新尚未开始项可更正/取消，已生效历史锁定。当前 ABI 与运营步骤见[编码规格 §7 D-37](./CODING_SPEC_V1.md#7-角色报告计量日和额度)和[准入标准 §4](./TOKEN_ADMISSION_STANDARD_V1.md#4-公司行动与数据单位)。

Token 提前或推迟更新不改变额度切换时刻；逐笔计股仍使用实时 Adapter。合约不能识别公告/源数据单位，也不主动统一多个 Token 的法律单位或拦截发行方日内变化。剩余工作是报告服务与真实发行方单位验证、异常监控和暂停/恢复演练，继续归 TG-10/TG-12。

## 建议推进顺序

1. **先补可在本仓库完成的边界：TG-01～TG-04。**每项比较错误及失败状态；不为了追百分比伪造正常业务状态。
2. **并行准备生产输入与发布证据：TG-06～TG-09、TG-12、TG-13、TG-15。**真实配置/产物未取得时保留待验收状态，按对象解除阻断。
3. **联测链下服务：TG-10、TG-11。**需要服务实现及其测试环境；这些场景不能靠 Solidity 单元测试独立完成。
4. **持续扩展模型：TG-05。**先选择资金、权限、单位、日期交错的高价值组合，再提高 seed/步数；有限测试不提供所有输入/任意序列的穷举证明。
5. **按产品范围启用 TG-14。**保留“不适用”依据或补齐实际使用路径。

TG-01～TG-05 是代码测试工作；生产与链下项包含真实配置、实现交付和外部验收，不能只靠增加测试函数解决。独立安全审计与发行方书面批准等发布证据继续按[部署清单](./DEPLOYMENT_CHECKLIST_V1.md)执行，本次不把它们算成未写的单元用例。

## 维护方式

后续新增发现先归入已有 ID；不同验收对象才新增 ID。完成时记录测试文件、执行日期/seed/配置、通过日志及保留限制；生产用例另存固定区块、地址/codehash、实际账户与产物依据。部分完成的组保留其剩余子项，不能因为同领域有一条成功用例就整组关闭。

原始基线记录在忽略的 `out/`：`tsv-operations-all-tests-v2.log`、`tsv-operations-coverage-v2.log`、`tsv-operations-coverage.lcov` 及历史 `tsv-final-fork-tests-v2.log`。运行与目录约定见[测试维护说明](../test/README.md)。
