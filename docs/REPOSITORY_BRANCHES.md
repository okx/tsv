# 开发与发布流程

| 分支 | 用途 | 规则 |
| --- | --- | --- |
| `main` | 合约、测试、技术文档、ABI、构建与集成代码、环境地址及发布信息 | 通过 MR 审核后更新 |
| `release/prod/<version>-<YYYYMMDD>` | 已审核版本的发布快照 | 固定源码、依赖及编译设置；不覆盖已发布版本 |

## 日常修改

合约、测试、通用构建和 SDK 修改通过 MR 进入 main。变更应包含必要的文档与 ABI／存储布局更新，并执行与改动相适应的检查。

独立发行方 Checker 属于外部集成。本仓库通过公开接口与其交互，TSV 核心构建不要求发行方实现源码。

## 正式发布

1. 固定完整源码 commit、依赖版本及编译参数，完成构建和测试。
2. 核对目标链部署输入、构造参数、链接库及代理实现，区分本地模拟与链上结果。
3. 更新[环境地址](../deployment/README.md)和发布说明；业务验收范围应单独记录。
4. 从已审核版本创建发布分支与版本 Tag，确认二者对应预期快照。
5. 发布 Release，记录版本变化、验证结果及适用边界。后续修复使用新版本，不移动既有 Tag。

分支或 Tag 的存在不代表目标链部署、权限配置或业务验收已经完成。实际状态应根据记录的链和核验区块独立检查。
